# Продакшен

Боевой сервер — **общий**: на нём работает ещё несколько проектов, а порты 80 и
443 занимает их общий nginx. Поэтому наш стек не публикует портов наружу: три
веб-сервиса подключаются к сети этого nginx, и он ходит в них по именам
контейнеров.

```
              общий nginx (client_nginx_prod, порты 80/443)
                 │
                 ├── cherkesov.mediann.dev        → parusa-client:3000
                 ├── admin.cherkesov.mediann.dev  → parusa-admin:3001
                 └── api.cherkesov.mediann.dev    → parusa-backend:8000
                                                       ├── parusa-postgres
                                                       └── parusa-minio
```

| Что | Адрес |
|---|---|
| Сайт | https://cherkesov.mediann.dev |
| Админка | https://admin.cherkesov.mediann.dev |
| API и Swagger | https://api.cherkesov.mediann.dev/docs |
| Каталог на сервере | `/opt/parusa` |
| Репозиторий | https://github.com/MalikProtopopov/alye-parusa |

## Ежедневная работа

```bash
ssh root@СЕРВЕР
cd /opt/parusa
make deploy        # git pull → пересборка → перезапуск → врезка в nginx
```

`make deploy` не трогает базу и загруженные файлы: они живут в томах докера.

Все команды — `make help`. Основные:

| Команда | Что делает |
|---|---|
| `make deploy` | обновить из git и перезапустить |
| `make ps` · `make logs` | состояние и логи (`make logs S=backend`) |
| `make backup` | дамп базы и архив файлов в `backups/` |
| `make db-restore FILE=…` | восстановить базу из дампа |
| `make clean-test-data` | удалить все заявки (боевая база должна быть чистой) |
| `make nginx` | перечитать врезку доменов в общий nginx |
| `make ssl` | выпустить недостающие сертификаты |

## Первая установка на новом сервере

```bash
git clone https://github.com/MalikProtopopov/alye-parusa.git /opt/parusa
cd /opt/parusa
make install
```

`make install` создаст `deploy/.env.prod` со случайными паролями, соберёт
образы, поднимет стек, врежет домены в nginx, выпустит сертификаты и покажет
доступы в админку. **Сохраните их — второй раз они не покажутся.**

Порядок внутри важен и соблюдается автоматически: nginx сначала отдаёт только
http и ACME-проверку, потом выпускаются сертификаты, и лишь затем добавляются
https-блоки. Иначе получился бы замкнутый круг: без сертификата nginx не
стартует, а без nginx не пройти проверку.

Перед установкой убедитесь, что A-записи всех трёх доменов указывают на сервер:
`make ssl` это проверяет и пропускает домен, который смотрит в другое место, —
иначе Let's Encrypt откажет и потратит попытку из недельного лимита.

## Секреты

`deploy/.env.prod` создаётся на сервере командой `make env` и **в git не
попадает** — репозиторий публичный. Там лежат пароль базы, ключ подписи
токенов, доступ к хранилищу и пароли учёток админки.

| Переменная | Зачем |
|---|---|
| `SITE_DOMAIN` `ADMIN_DOMAIN` `API_DOMAIN` | домены; используются и в сборке фронтендов, и в nginx |
| `POSTGRES_PASSWORD` | пароль базы |
| `JWT_SECRET` | подпись токенов; смена разлогинивает всех |
| `S3_ACCESS_KEY` `S3_SECRET_KEY` | доступ к хранилищу файлов |
| `SEED_*_EMAIL` `SEED_*_PASSWORD` | учётки админки, создаются при первом старте |
| `TELEGRAM_BOT_TOKEN` `TELEGRAM_CHAT_ID` | уведомления о заявках |

`NEXT_PUBLIC_*` вшиваются в бандл **на этапе сборки**. Сменили домен — нужна
пересборка (`make build`), правки в `environment` уже ничего не изменят.

## Домены и nginx

Общий конфиг лежит в `/opt/mediannfront/nginx/nginx.conf` и обслуживает все
проекты сервера. Наш кусок в нём ограничен маркерами:

```
# >>> parusa (Алые Паруса) — управляется deploy/nginx-apply.sh, вручную не править
…
# <<< parusa
```

`make nginx` перегенерирует только этот кусок. Перед записью делается резервная
копия с отметкой времени, после — `nginx -t`; если конфиг не принят, файл
возвращается из копии и чужие проекты не страдают.

Апстримы заданы через переменные (`set $parusa_client parusa-client:3000`) —
это заставляет nginx резолвить имена в рантайме, и он не падает при старте,
пока наши контейнеры пересобираются.

## Сертификаты

Выпускаются certbot-ом в тома общего nginx, по отдельному сертификату на домен.
Продление — `/opt/renew-certs.sh` в cron по понедельникам в 4:17. Скрипт трогает
**только наши три сертификата**: у остальных проектов свои задания, и чужая
неудача не должна ронять наш прогон.

Проверить срок:

```bash
echo | openssl s_client -servername cherkesov.mediann.dev \
  -connect cherkesov.mediann.dev:443 2>/dev/null | openssl x509 -noout -enddate
```

## Резервные копии

```bash
make backup                         # база + файлы в backups/
make db-restore FILE=backups/db-20260811-190000.sql.gz
```

Нужны обе части: база хранит имена файлов, хранилище — сами файлы. Дамп
снимается с `--clean --if-exists`, поэтому восстановление не требует удаления
базы и работает на живом стеке.

## После запуска

- Подключить домен в Яндекс.Вебмастере и Google Search Console, вставить коды
  подтверждения в **Настройки** админки.
- Отправить `sitemap.xml` в оба сервиса.
- Вставить номер счётчика Метрики в **Настройки**.
- Заполнить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `deploy/.env.prod`,
  выполнить `make up` и проверить кнопкой «Отправить тестовое сообщение».
- Сменить пароли учёток админки на свои.
- Убедиться, что в **Документах** есть активная Политика обработки данных: на
  неё ссылаются формы сайта (152-ФЗ).
