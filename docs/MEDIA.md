# Медиа сайта

Первый экран сайта — не видеофайл, а **секвенция кадров, которую прокручивает
скролл**: пустой берег превращается в готовый квартал, день переходит в ночь.
Так сделано потому, что честный скраб видео по прокрутке ломается на iOS и
Safari, а последовательность JPEG работает везде одинаково.

## Что откуда берётся

```
materials/seedance-output/            ← исходники (в репозитории, не публикуются)
├── morph-construction/C1…C5.mp4        морф стройки: пустой берег → ночь
└── flythroughs/F1…F3.mp4               облёты комплекса
materials/renders/*.png                 рендеры архитектора

          ↓  web/scripts/prepare-media.sh (нужен ffmpeg)

web/public/media/                     ← то, что реально отдаётся браузеру
├── hero/frames/frame-###.jpg + manifest.json   152 кадра — первый экран
├── hero/poster.jpg                             первый кадр (пока грузится секвенция)
├── hero/morph-hero.mp4                         запасное видео для reduced-motion
├── story/frames/…                              фон скролл-истории «Жизнь у моря»
├── flythroughs/f1…f3.mp4 + постеры             облёты
└── renders/*.jpg                               рендеры, сжатые под веб
```

## Пересборка

```bash
cd web && npm run prepare:media
```

Скрипт идемпотентен — можно гонять сколько угодно. Параметры через переменные
окружения: `HERO_FPS` (по умолчанию 6 — примерно 150 кадров на 25 секунд
морфа), `HERO_WIDTH` (1280), `HERO_Q` (качество JPEG, 6 ≈ хороший компромисс).

`manifest.json` рядом с кадрами описывает количество, шаблон имени и размеры —
компонент hero читает его и не хардкодит число кадров. Если поменял `HERO_FPS`,
манифест обновится сам.

Промежуточные файлы (склеенный морф целиком) складываются в `web/.media-cache` и
в `public/` не попадают — иначе они уехали бы в продакшен-образ.

## Иконки и OG-обложка

```bash
cd web && npm run prepare:icons
```

Генерирует favicon, apple-icon, иконки 192/512 и обложку `og-cover.png`
1200×630 для соцсетей — всё из постера первого экрана.

## Вес

`web/public/media` — около 80 МБ, и это попадает в образ сайта. Причина, по
которой оно лежит в репозитории, а не в объектном хранилище: кадры первого
экрана должны отдаваться с того же домена и кэшироваться навсегда, а их имена
неизменны. Caddy проставляет на `/media/*` годовой иммутабельный кэш.

Загрузки контент-менеджера — другая история: они идут в MinIO/S3 и отдаются
через `/cms-media/*` (см. [ARCHITECTURE.md](ARCHITECTURE.md#хранилище-файлов)).

## Правки видео

Исходные клипы генерировались нейросетью по покадровому сценарию; описания
сцен и опорные кадры лежат в [materials/seedance-input/](../materials/seedance-input/)
и [materials/seedance-output/README.md](../materials/seedance-output/README.md).
Чтобы заменить сцену — положи новый файл под тем же именем в
`materials/seedance-output/morph-construction/` и перегони `prepare:media`.

Важное свойство исходников: **в видео нет ни одной надписи**. Все тексты
первого экрана — HTML поверх кадров, они правятся в админке («Главы первого
экрана») и переводятся без перегенерации видео.
