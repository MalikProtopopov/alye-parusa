# Разработка

## Через Docker (быстрее всего)

```bash
docker compose up --build
```

Поднимет PostgreSQL, MinIO, бэкенд, сайт и админку. Схема базы и seed-контент
создаются автоматически при старте бэкенда.

Полный сброс (база + загруженные файлы): `docker compose down -v`.

## Без Docker (когда правишь код)

Нужны Python 3.11+, Node 20+ и PostgreSQL. Базу удобно поднять контейнером, а
приложения запускать локально — так работает hot reload.

### 1. База

```bash
docker run -d --name parusa-dev-pg -p 55444:5432 \
  -e POSTGRES_USER=parusa -e POSTGRES_PASSWORD=parusa -e POSTGRES_DB=parusa \
  postgres:16-alpine
```

Порт 55444 вместо 5432 — чтобы не конфликтовать с другими проектами на машине.
Если контейнер уже создавали, поднять его снова: `docker start parusa-dev-pg`.

> **Симптом «Не удалось соединиться с сервером» при входе в админку** почти
> всегда означает, что контейнер базы остановлен: бэкенд отвечает 500 без
> CORS-заголовков, и браузер показывает сетевую ошибку вместо серверной.
> Лечится `docker start parusa-dev-pg`.

### 2. Бэкенд

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
DATABASE_URL='postgresql+psycopg2://parusa:parusa@localhost:55444/parusa' \
CORS_ORIGINS='http://localhost:3000,http://localhost:3001,http://127.0.0.1:3000,http://127.0.0.1:3001' \
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Swagger — http://localhost:8000/docs.

### 3. Сайт и админка

```bash
cd web            && npm install && npm run dev        # http://localhost:3000
cd frontend-admin && npm install && npm run dev        # http://localhost:3001
```

Переменные окружения — из `.env.example` в каждой папке. Минимум:

| Переменная | Где | Зачем |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | сайт, админка | адрес API для браузера |
| `API_URL` | сайт | адрес API для серверного рендера (в Docker — `http://backend:8000`) |
| `NEXT_PUBLIC_SITE_URL` | сайт, админка | канонический адрес сайта: canonical, OG, sitemap, ссылки «Посмотреть на сайте» |
| `NEXT_PUBLIC_SHOW_DEMO_CREDS` | админка | показывать демо-доступы на экране входа (только для разработки) |

Если порты 3000/3001/8000 заняты другими проектами, запускай на своих
(`npm run dev -- -p 3002`, `uvicorn … --port 8001`) и не забудь про
`NEXT_PUBLIC_API_URL` и `CORS_ORIGINS` — иначе браузер заблокирует запросы.

## Тесты

```bash
# бэкенд — 122 теста, нужна отдельная тестовая база
docker run -d --name parusa-test-pg -p 55433:5432 \
  -e POSTGRES_USER=parusa -e POSTGRES_PASSWORD=parusa -e POSTGRES_DB=parusa_test \
  postgres:16-alpine
cd backend && pytest -q

# сайт — 70 тестов (домен, SEO-билдеры, sitemap)
cd web && npm test
```

Тесты бьют по базе на порту 55433 (или `TEST_DATABASE_URL`) и дропают схему до и
после сессии — на dev-базу не влияют.

## Гейты перед коммитом

```bash
cd backend        && pytest -q
cd web            && npm run typecheck && npm run lint && npm test && npm run build
cd frontend-admin && npx tsc --noEmit && npm run build
```

Сборка сайта проходит **без запущенного бэкенда** — это осознанное свойство:
статические адаптеры подхватывают контент, если API недоступен. Если сборка
падает без API, значит где-то потеряли фолбэк.

## Грабли

**Смешанная сборка `.next`.** Два параллельных `npm run build` в одной папке
перезаписывают общий каталог `.next`, и получается франкенштейн из старых и
новых чанков — приложение выглядит сломанным без единой ошибки в логе. Тот же
эффект даёт `npm run build` при запущенном `npm run dev`: рабочий dev-сервер
начинает отдавать 500 с `Cannot find module './NNNN.js'`, а страница приходит
пустой. Лечится `rm -rf .next` и перезапуском dev-сервера. Правило: не собирать
приложение, пока в этой же папке работает dev.

**Порты и env при перезапуске.** Переменные вроде `NEXT_PUBLIC_API_URL`
вшиваются в бандл, поэтому dev-сервер, поднятый без них, молча уходит на
дефолтный `localhost:8000` — вход в админку перестаёт работать без внятной
ошибки. Держи локальные значения в `.env.local` (он есть в `.dockerignore` обоих
фронтендов и в образ не попадает), а не в командной строке.

**Изменение схемы базы.** Alembic не используется — см.
[ARCHITECTURE.md](ARCHITECTURE.md#схема-базы-без-alembic). Добавил поле в
`models.py` — добавь идемпотентный `ALTER TABLE … ADD COLUMN IF NOT EXISTS` в
`main.py`, иначе на существующей базе будет 500.

**Проценты в калькуляторе.** API хранит доли (`0.3`), админка показывает
проценты (`30`). Новое процентное поле помечай `percent: true` в конфиге
ресурса, иначе значение уедет в сто раз.

**Пути к картинкам.** В базе только относительные `/media/<имя>`. Абсолютный
URL с доменом попадать в базу не должен — при смене окружения такие ссылки
ломаются все разом.

**Кэш сайта.** После правки в админке страница обновится в течение минуты
(ISR). Если проверяешь правку немедленно — перезапусти `npm run dev` или жди
ревалидацию, это не баг.

## Адаптив: чем ломается вёрстка

Проверено инструментально на ширинах 320–1024 px по всем типам страниц. Три
механизма, которые ломали раскладку, — и почему они неочевидны:

**`1fr` не умеет быть уже своего содержимого.** У колонки `1fr` минимальный
размер по умолчанию равен `min-content`, поэтому одно длинное слово
(«05:09:000045:476») раздвигает колонку, а за ней и всю страницу. Лечится
`min-width: 0` на элементе сетки — либо переходом в одну колонку на узких
экранах. Сетку с фиксированным числом колонок нельзя задавать по умолчанию:
только внутри `@media (min-width: …)`.

**Нижняя граница `clamp()` в типографике.** Минимум шкалы применяется только
ниже точки пересечения — если средняя часть формулы на 320 px даёт больше
минимума, минимум не участвует вовсе. Чтобы уменьшить кегль на телефоне,
пересчитывать надо среднюю часть, а не минимум.

**`overflow-x: hidden` на `body` маскирует переполнение.** Страница не
прокручивается вбок, поэтому проблему не видно — вместо этого текст молча
обрезается по краю экрана. Проверять надо не глазами, а сравнением
`documentElement.scrollWidth` с `clientWidth`.

Проверка автоматизирована — при поднятом сайте:

```bash
cd web && npm run audit:responsive          # 9 страниц × 6 ширин
SITE_URL=http://localhost:3002 npm run audit:responsive   # если порт другой
```

Скрипт проходит все типы страниц на ширинах 320–1024, сравнивает
`scrollWidth` с `clientWidth`, называет виновников (элементы, выходящие за
экран и не лежащие внутри намеренно прокручиваемой ленты) и заодно собирает
цели нажатия мельче 36 px. Возвращает ненулевой код, если нашлось
переполнение, — годится для гейта перед релизом.
